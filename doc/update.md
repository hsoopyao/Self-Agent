## 已发现的优化项

### P0：稳定性与正确性（建议在 v1.1.x 完成）

- [ ] **统一 LLM 创建方式**：`rag_chain.py`、`general_chat.py` 和 `direct_chat.py` 在模块导入时就创建模型实例，设置页切换模型后，已创建的实例可能不会立即更新。建议建立按“模型名 + 参数”缓存的 LLM 工厂。
- [ ] **实现真正的搜索超时**：`search_with_timeout()` 虽然接收 `timeout` 参数，但当前没有将它应用到请求；网络异常时仍可能长时间阻塞。
- [ ] **改善错误边界**：不要在用户页面直接展示完整 traceback，避免泄露路径、配置或第三方接口信息；详细错误应仅写入日志。
- [ ] **启动前配置检查**：对 `BIGMODEL_API_KEY`、`TAVILY_API_KEY`、模型名称和模型文件进行集中校验，通过页面给出可操作提示，避免导入模块时整个应用崩溃。
- [ ] **使用绝对项目路径**：当前 `prompts/`、`data/` 和 `chroma_db/` 依赖启动时的工作目录，建议基于 `Path(__file__)` 统一解析，确保从任意目录启动都正常。
- [ ] **恢复安全的环境变量模板**：提供不包含真实密钥的 `.env.example`，并在 README 中保持同步。
- [ ] **固定可复现的依赖版本**：当前 `requirements.txt` 大量使用无上限的 `>=`，未来发布可能因主版本升级突然不兼容。建议增加锁定文件或合理上限。
- [ ] **收紧 HTML 渲染边界**：ReAct 观察卡片使用 `unsafe_allow_html=True` 展示外部搜索摘要与链接，建议转义摘要和 URL，仅允许必要的安全链接标签。
- [ ] **迁移 Tavily 工具**：当前 `langchain_community.tools.TavilySearchResults` 已弃用，建议迁移到 `langchain-tavily` 的 `TavilySearch`，避免后续 LangChain 升级时中断。

### P1：性能与体验（建议在 v1.2.0 完成）

- [ ] **路由快速通道**：问候、天气、新闻等明确意图可先用规则判断，仅在模糊问题上调用 LLM 路由，降低延迟和 API 成本。
- [ ] **ReAct 预算与终止策略**：按意图限制工具数量、记录每轮搜索查询，并对重复或低价值操作提前终止。
- [ ] **网络搜索引用**：最终答案保留多条来源的标题、URL 和抓取时间，不只展示第一个结果。
- [ ] **RAG 检索升级**：增加关键词 + 向量混合检索、Reranker 重排、可配置 Top-K 及文档级过滤。
- [ ] **索引进度与任务化**：大文件解析和 Embedding 放入后台任务，页面展示进度、失败原因和重试入口。
- [ ] **回答交互**：新增停止生成、重新生成、复制、点赞/点踩和导出对话。
- [ ] **设置持久化**：将主题和调优参数保存到本地配置，避免刷新或新会话后重置。

### P2：产品化能力（v1.3.0 及之后）

- [ ] 多 LLM 提供商和本地模型切换（智谱、OpenAI 兼容接口、Ollama 等）。
- [ ] 多知识库、标签、文件夹和文档权限隔离。
- [ ] 多用户登录、会话持久化和设备间同步。
- [ ] 语音输入/语音播放、图片理解及 OCR。
- [ ] 管理后台：请求数、延迟、Token 成本、工具成功率和 RAG 命中率。
- [ ] 建立评测集和自动化测试，覆盖路由、RAG 命中、ReAct 终止、文件导入和上下文压缩。

## 版本与分支建议

### 当前这次是否需要新建版本分支？

**本次不需要再新建长期 `v1.0` 分支。** 当前已按要求直接在 `main` 上完成修改。主题切换属于向后兼容的新功能，按语义化版本更适合从 `v1.0.0` 升级到 `v1.1.0`。

建议流程：

1. `main` 始终保持可运行。
2. 完成并验证本次功能后，在 `main` 打 `v1.1.0` Git Tag。
3. 后续较大功能使用短期功能分支，例如 `feature/llm-factory`、`feature/hybrid-search`，完成后合并回 `main`。
4. 只有在需要同时维护 v1.0 老用户并单独发布热修复时，才需要创建 `release/v1.0` 维护分支。
5. 不要只用分支代替版本标记；对外发布仍应使用 `v1.0.0`、`v1.1.0` 等 Git Tag。
